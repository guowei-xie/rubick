# L1 续报率归因（含质量验证）

本工作流合并原 B5（续报率归因）与 B6（续报质量验证），覆盖「为什么续报率低于目标/历史」+「下钻定位的渠道组合具体出了什么质量问题」全链路。归因公式与漏斗算法已抽到 method 资产，本 workflow 只描述步骤与输出形态。

## 依赖的 method 资产
- `mth_l1_flow_next_maturity_adjustment` — 流入下一期成熟度判断与预测修正（消费其产出的 `market_sales_actual_flow_adjusted` 缓存）
- `mth_l1_structural_attribution` — 结构归因统一公式（SKU / 智配-非智配 / 渠道层 / 城市线级 / 支付年级 / 渠道组 维度都用它）
- `mth_l1_funnel_chain_substitution` — 过程漏斗连环替代法（质量验证最后一块——过程漏斗归因块）

## 适用问题
- 为什么续报率未达标。
- 为什么当前期续报率较历史基准下降或提升。
- 续报率变化来自 SKU 结构变化还是 SKU 自身续报率变化。
- 哪个 `业务核算组 + 定标渠道类型` 或 `招生分配类型` 拖累/拉动续报率。
- 定位出的渠道组合背后是结构变差、同结构续报率变差还是过程承接变差。

## 不适用范围
- 不输出招生达成/未达成判断（走 `wf_l1_admission_diagnosis`）。
- 不替代渠道趋势图片解读（走 `wf_l1_channel_trend_diagnosis`）。
- 不重新执行流入下一期预测修正——**只消费当天有效修正缓存**。未预测修正的不成熟期次只展示风险，不进入正式归因。
- 不输出预测修正明细、完整渠道扫描报告、独立行动清单或泛化建议。

## 必要输入
| 输入 | 规则 |
|---|---|
| 分析渠道 | 精确匹配 `大班型_渠道来源` |
| 当前期 | 1 个或多个连续 `学期期次`，整体归因，不逐期拆 |
| 比较类型 | 默认 `全部`；可指定 `对比目标` / `对比历史` |
| 历史基准期 | 可选；未提供时默认取当前窗口之前连续 N 个期次 |

## 步骤

### Step 1 · 前置成熟度处理
对当前窗口和历史基准窗口都执行或确认 `mth_l1_flow_next_maturity_adjustment`：
- 当天有效且覆盖两个窗口的 `market_sales_actual_flow_adjusted` 存在 → 两个窗口都优先使用修正后实际数据
- 否则必须确认两个窗口都成熟或不受流入下一期未成熟影响后，才能用 `market_sales_actual`

### Step 2 · 主归因（按 `mth_l1_structural_attribution`）
按比较类型分别计算（`comparison_type=全部` 时两套都做）：
- **对比目标**：基期 = 当前窗口目标数据，现期 = 当前窗口实际或修正后实际
- **对比历史**：基期 = 历史基准窗口实际或修正后实际，现期 = 当前窗口实际或修正后实际

**归因层级（固定顺序）**：
1. SKU 层：保留全部 SKU，按 `总影响` 排序；下降场景升序解释主导拖累，上升场景降序解释主导拉动；**全量 SKU 都必须拆解**，不得只拆最大影响 SKU。
2. SKU 内智配/非智配：所有 SKU 均按 `招生分配类型` 拆解。
3. 渠道层：每个 SKU 内，`智配班型` 或 `非智配班型` 现期招生占比 `>= 10%` 时按 `业务核算组 + 定标渠道类型` 完整拆解；`< 10%` 不下钻。

### Step 3 · 质量验证范围移交（内化原 market_renewal_quality_handoff）
当 Step 2 渠道层出现**任一**局部负向总影响项时，将 `sku + 招生分配类型 + 业务核算组 + 定标渠道类型` 固化为质量验证范围。完全无负向项时跳过 Step 4 并说明「无须进入质量验证」。

### Step 4 · 质量验证（仅在 Step 3 移交了范围时）
**输入范围严格固定为 Step 3 移交集合**，不得自行扩大。

固定 4 个验证块（前 3 用 `mth_l1_structural_attribution`，第 4 用 `mth_l1_funnel_chain_substitution`）：
1. **城市线级质量归因**：判断城市线级结构变化或同线级续报率变化
2. **支付年级质量归因**：判断年级结构变化或同年级续报率变化
3. **渠道组质量归因**：先判断渠道组续报率变化覆盖面、再判断降幅分布——「普降 / 高权重放大 / 单点异常」三选一；**不得**先按总影响下结论
4. **过程转化漏斗归因**：连环替代法 `加微率 → 加微首到率 → 首到留存率 → 完课转化率`

**渠道组判断细则**：
- 多数有量渠道组同向下降 → 「渠道组普降为主」
- 某渠道组 `总影响` 最大但降幅并不异常，只因当前招生占比大放大影响 → 「高权重普降代表 / 结构放大来源」；**禁止**写成「特别异常渠道组」
- 某渠道组续报率降幅明显深于多数渠道组且当前招生量足以支撑 → 「单点异常渠道组」

**预测修正使用规则**：
- 质量验证下钻维度**禁止**使用分摊预测补充续报量
- 城市线级 / 支付年级 / 渠道组下钻只用观测口径：`期内续报量 / 实际招生量`
- 预测补充续报量**只**在移交范围总计层展示，不分配到下钻维度
- 过程漏斗可在移交范围总计层使用修正后续报量，但不得继续下钻
- 质量验证图片或表格必须备注说明该口径

## 固定输出结构
1. **整体结论汇总**：高度总结、咨询风格、结论先行；说明相对目标和历史的双重状态、归因主线、质量验证优先级、是否使用预测修正口径。归因主线必须描述为「流入智配项目流量占大头，且该流量续报率下降/低于基准」；**禁止**笼统写成「智配班型续报质量同步回落」。
2. **关键数据支撑**（≤ 3 条）：固定为 `目标缺口` / `历史趋势` / `归因指向收敛`；比较类型不含某项时自动省略。
3. **一、对比目标归因**（`comparison_type` 含 `对比目标` 时）：SKU 总览 → 每个 SKU 输出 `SKU 结论 + 智配/非智配拆解 + 渠道层拆解`。SKU 结论一句话回答：影响方向和强度、是否主要来自流入智配项目流量占比高且续报率下降/低于基准、渠道层首要验证对象。
4. **二、对比历史归因**（`comparison_type` 含 `对比历史` 时）：同上结构。
5. **质量验证结论**（仅在 Step 3 移交了范围时）：固定顺序 `城市线级 → 支付年级 → 渠道组 → 过程漏斗 → 综合解释`；缺字段块保留标题说明缺失。综合解释必须区分：结构变差 / 同结构续报率变差 / 过程承接变差。

## 归因表字段（每张归因表通用）
分组维度 / 基期招生量 / 现期招生量 / 基期招生占比 / 现期招生占比 / 基期续报率 / 现期续报率 / 结构影响 / 续报率影响 / 总影响。对比目标时基期列命名「目标」；对比历史时基期列命名「历史」。每张表追加 `总计` 行。

## 数字展示规则
- 续报率、招生占比：1 位 `%`。
- 结构影响、续报率影响、总影响：2 位 `%`；非零但 `|x| < 0.01%` 显示为 `<0.01%` / `>-0.01%`。
- **禁用** `pp` / 百分点 / 百分比点；禁止把非零影响渲染成 `0.0%` 或 `0.00%`。
- 影响值按方向红/绿标识；总计行加粗/底色突出。

## 交付载体
- **默认交付载体 = 飞书云文档**：归因表用 **Markdown 表格** 在云文档内呈现，合法。
- **PPT 风格只约束视觉规范**（字号 / 对齐 / 留白 / 重点标注 / 颜色），不约束载体；表格内不要写 `pp` / 百分点等被禁的口径表述。
- **仅当用户显式要求 PPT / 导出图片时**，才走图片化输出路径；不主动建议导出 PPT。

## 反面 case（一律判跑偏）
- 未确认成熟度直接用 `market_sales_actual` 归因。
- 把续报率目标缺口写成招生达成/未达成。
- 对比目标和对比历史混用同一个基期。
- `comparison_type=全部` 时漏掉对比历史相关数据/结论/图片。
- 新增 SKU / 新增渠道组合基期续报率填 0（违反 `mth_l1_structural_attribution` 的新增分组保护规则）。
- 只输出 SKU 表 / 只拆最大影响 SKU。
- 每个 SKU 只写结论，不输出渠道层拆解。
- 智配/非智配占比 `< 10%` 仍下钻渠道层。
- 整体结论简写为「智配班型续报质量同步回落」。
- 渠道层存在负向项却只输出移交，不生成质量验证结论。
- 质量验证下钻维度使用分摊预测补充续报量。
- 把渠道组「高权重放大」写成「单点特别异常」。
- 总计行对续报率/招生占比/影响值做算术平均。
- 用户未要求时主动建议导出 PPT 或把云文档表格转图片。
